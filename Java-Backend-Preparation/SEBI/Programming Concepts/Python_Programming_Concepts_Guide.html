011. Programming Fundamentals

1.1 Variables

A variable is a named reference to a memory location that stores a value. In Python, a variable is created the moment you assign a value to it — there is no separate declaration step.

x = 10          # x is bound to an integer object
name = "Alice"  # name is bound to a string object
x = "now text"  # x can be rebound to a different type

Key ideas:

  • Python variables are names bound to objects, not fixed memory boxes with a type. The name x is just a label pointing to whatever object is currently assigned.
  • Multiple names can point to the same object (aliasing): a = [1,2]; b = a — both a and b refer to the same list.
  • Variable naming rules: must start with a letter or underscore, can contain letters/digits/underscores, case-sensitive, cannot be a reserved keyword.
  • Python uses dynamic typing — the type is attached to the object, not the variable name, so the same name can be reassigned to any type.
  • Variables in Python are created at first assignment and destroyed by garbage collection when no references remain (reference counting + cycle detector).

1.2 Data Types

Python's built-in data types are grouped into: numeric (int, float, complex), sequence (str, list, tuple, range), mapping (dict), set types (set, frozenset), boolean (bool), and NoneType.

i = 10            # int  (arbitrary precision)
f = 3.14          # float (double precision)
c = 2 + 3j        # complex
s = "hello"       # str (immutable sequence of Unicode chars)
lst = [1, 2, 3]   # list (mutable, ordered)
tup = (1, 2, 3)   # tuple (immutable, ordered)
d = {"a": 1}      # dict (mutable key-value mapping)
st = {1, 2, 3}    # set (mutable, unordered, unique elements)
b = True          # bool
n = None          # NoneType
  • Python is dynamically and strongly typed: types aren't declared, but implicit unsafe coercions (like "2" + 2) raise errors rather than silently converting.
  • int in Python has arbitrary precision (no overflow, limited only by memory).
  • type() returns an object's type at runtime; isinstance() checks type membership including subclasses.
  • Everything in Python — including functions, classes, and modules — is an object.

1.3 Operators

Python supports arithmetic, relational, logical, bitwise, assignment, identity, and membership operators.

7 // 2      # 3   → floor division
7 % 2       # 1   → modulo
2 ** 3      # 8   → exponentiation
5 == 5.0    # True → value equality
a is b      # identity comparison (same object in memory)
3 in [1,2,3]# True → membership test
True and False  # logical AND (returns operand, not just bool)
  • // floor division and ** exponentiation are unique operators not directly available (as symbols) in C/C++/Java.
  • and, or, not are keyword-based logical operators (not &&, ||, !), and they perform short-circuit evaluation returning the actual operand, not just True/False.
  • is compares object identity (memory address); == compares value equality. This distinction is unique in emphasis to Python.
  • in / not in are membership operators for sequences and collections.
  • No ++ or -- operators in Python.

1.4 Expressions

An expression is any valid combination of values, variables, operators, and function calls that evaluates to a value.

result = (a + b) * c - d / 2
is_valid = (x > 0) and (x < 100)
squares = [i**2 for i in range(10)]   # list comprehension is an expression
value = x if x > 0 else -x            # conditional (ternary) expression
  • Python supports list/dict/set/generator comprehensions as compact expressions — a feature not natively present in C/C++/Java.
  • The ternary conditional expression syntax is value_if_true if condition else value_if_false (unlike C/Java/C++'s condition ? true_val : false_val).
  • Expressions can be chained: 1 < x < 10 is valid Python (equivalent to 1 < x and x < 10), which is not valid in C/C++/Java.

1.5 Statements

A statement is an instruction that performs an action (assignment, control flow, import, etc.), as opposed to an expression which produces a value.

x = 5                  # assignment statement
if x > 0:               # compound statement
    print("positive")
import math             # import statement
def greet(): pass       # function definition statement
  • Python uses indentation to define statement blocks instead of braces {}.
  • Statements typically end with a newline; no semicolon required (though ; can separate multiple statements on one line).
  • Compound statements (if, for, while, def, class) always end with a colon :.

2.1 if / else

if x > 0:
    print("positive")

  • No parentheses required around the condition, but a colon : and indentation are mandatory.

2.2 switch

Python did not have a switch statement until match-case was introduced in Python 3.10 (structural pattern matching).

match command:
    case "start":
        print("Starting")
    case "stop":
        print("Stopping")
    case _:
        print("Unknown command")
  • match-case supports pattern matching (destructuring tuples, matching types, guards with if), which is more powerful than a plain C-style switch.
  • Prior to 3.10, developers simulated switch behavior using if-elif chains or dictionaries mapping values to functions.

2.3 loops

Python has two loop constructs: for (iterates over a sequence/iterable) and while (repeats while a condition holds).

for i in range(5):        # iterates 0..4
    print(i)

for item in [10, 20, 30]:  # iterates over any iterable
    print(item)

i = 0
while i < 5:
    print(i)
    i += 1

for i in range(5):
    else:                  # NOTE: for-else — runs if loop completes without break
        ...
  • Python's for loop is fundamentally iterator-based: it works over anything implementing the iterator protocol (__iter__/__next__), not a numeric counter like C.
  • Python uniquely supports for...else and while...else: the else block executes only if the loop finishes without hitting a break.
  • There is no traditional C-style for(init; cond; incr) loop in Python — you emulate it with range().

2.4 break / continue

for i in range(10):
    if i == 5:
        break       # exits the loop entirely
    if i % 2 == 0:

2.5 recursion

A function calling itself directly or indirectly to solve smaller subproblems until a base case is reached.

def factorial(n):
    if n <= 1:          # base case
        return 1
    return n * factorial(n - 1)   # recursive case
  • Python has a default recursion limit (typically 1000, adjustable via sys.setrecursionlimit()), because CPython does not implement tail-call optimization — deep recursion can raise RecursionError.
  • Every recursive call adds a new stack frame in Python's call stack, same conceptual model as C/C++/Java, but Python's limit is much lower and configurable in software rather than being purely OS-stack-size-bound.

033. Functions & Scope

3.1 Functions / Methods

def add(a, b=10):        # default parameter value
    return a + b

def variadic(*args, **kwargs):   # variable-length positional and keyword args
    print(args, kwargs)

  • Defined with def; functions are first-class objects — can be assigned to variables, passed as arguments, returned from other functions, and stored in data structures.
  • Support default arguments, keyword arguments, arbitrary positional (*args) and keyword (**kwargs) arguments, and lambda (anonymous) functions.
  • A "method" is simply a function defined inside a class; it implicitly receives the instance as its first parameter (self).
  • No function overloading by signature (Python resolves by the single most recent def with that name); default/variadic args are used to simulate it.

3.2 Scope

Python scoping follows the LEGB rule: Local → Enclosing → Global → Built-in.

x = "global"

def outer():
    x = "enclosing"
    def inner():
        nonlocal x       # refers to enclosing scope's x
        x = "modified"
    inner()
    print(x)              # "modified"

def f():
    global x
    x = "changed globally"
  • Local scope: names assigned inside a function.
  • Enclosing scope: names in the local scope of any enclosing function (closures).
  • Global scope: names assigned at the top level of a module.
  • Built-in scope: names preassigned by Python (len, print, etc.).
  • Unlike C/Java/C++, Python does not create a new scope for blocks like if, for, while — only functions (and classes, partially) create new scopes.
  • global and nonlocal keywords are required to modify variables from outer scopes inside a function.

3.3 Lifetime

Lifetime refers to how long an object/variable exists in memory.

  • Python objects live as long as there is at least one reference to them (reference counting), plus a cyclic garbage collector to clean up reference cycles.
  • Local variables' *bindings* die when the function returns, but the *objects* they reference may persist if referenced elsewhere (e.g., returned, or captured by a closure).
  • Global variables live for the duration of the program (module's lifetime).

3.4 Parameter Passing

Python uses "pass by object reference" (also called "pass by assignment"): the function receives a reference to the same object, but rebinding the parameter name inside the function does not affect the caller's variable. However, mutating a mutable object (like a list) *does* affect the caller.

def modify_list(lst):
    lst.append(4)      # mutates the shared object — visible outside

def reassign(lst):
    lst = [100]         # rebinds local name only — NOT visible outside

nums = [1, 2, 3]
modify_list(nums)   # nums is now [1, 2, 3, 4]
reassign(nums)       # nums is still [1, 2, 3, 4]

3.5 Binding

Binding refers to associating a name with an object/value, and *when* that association happens.

  • Python is dynamically bound / late-bound: names are resolved at runtime, not compile time. A name lookup happens each time the code executes.
  • Function/method calls in Python are resolved dynamically (duck typing) — there's no need for explicit interfaces for polymorphism.
  • Variable rebinding is simply reassignment: x = x + 1 creates a new binding for x (doesn't mutate the old int object, since ints are immutable).

044. Programming Paradigms

4.1 Imperative Programming

Programming by giving the computer a sequence of explicit statements that change program state (variables) step by step.

total = 0
for n in range(1, 6):
    total += n
print(total)   # imperative: explicit steps mutate 'total'

Python fully supports imperative style — it's the default/most common style used for scripts, loops, and object mutation.

4.2 Functional Programming

Programming built around pure functions, immutability, and function composition rather than mutable state.

nums = [1, 2, 3, 4, 5]
squares = list(map(lambda x: x**2, nums))
evens = list(filter(lambda x: x % 2 == 0, nums))
from functools import reduce
total = reduce(lambda a, b: a + b, nums)
squares_comp = [x**2 for x in nums]   # more "Pythonic" functional-style alternative
  • Python supports functional tools: map(), filter(), reduce(), lambda, first-class functions, and comprehensions.
  • Python is not purely functional — it allows mutable state, side effects, and doesn't enforce immutability or referential transparency.

4.3 Logic Programming

A declarative paradigm where the programmer states *facts and rules*, and the system infers answers via logical inference (e.g., Prolog).

  • Python has no native logic-programming paradigm, but it can be simulated using libraries such as kanren (miniKanren-based) or by writing constraint-solvers manually, or using Prolog-interfacing libraries like pyswip.
  • Python's pattern-matching (match-case) and constraint libraries approximate some declarative-style logic but it is not a true logic-programming language.

055. Object-Oriented Programming (OOP)

5.1 Class

A class is a blueprint that defines attributes (data) and methods (behavior) for creating objects.

class Car:
    wheels = 4                 # class attribute (shared)

    def __init__(self, brand):  # constructor
        self.brand = brand      # instance attribute

    def drive(self):
        print(f"{self.brand} is driving")

5.2 Object

An object is an instance of a class — a concrete entity with actual attribute values in memory.

my_car = Car("Toyota")   # my_car is an object/instance of Car
my_car.drive()

Every Python value — even integers and functions — is technically an object of some class, unlike C++/Java where primitives are not objects.

5.3 Encapsulation

Bundling data and methods together and restricting direct access to some of an object's components.

class Account:
    def __init__(self, balance):
        self._balance = balance    # "protected" by convention (single underscore)
        self.__pin = "1234"        # "private" via name mangling (double underscore)

    def get_balance(self):
        return self._balance
  • Python has no true access modifiers (private/protected/public) enforced by the language. It relies on naming conventions:
  • _name → convention for "protected" (internal use), not enforced.
  • __name → triggers name mangling (_ClassName__name), making accidental access harder but still not truly private.
  • Properties (@property decorator) provide getter/setter-like encapsulation with clean syntax.

5.4 Abstraction

Hiding complex implementation details and exposing only essential features via a simplified interface.

from abc import ABC, abstractmethod

class Shape(ABC):
    @abstractmethod
    def area(self):
        pass          # must be implemented by subclasses

class Circle(Shape):
    def __init__(self, r):
        self.r = r
    def area(self):
        return 3.14 * self.r ** 2
  • Achieved via the abc module (ABC, @abstractmethod) to define abstract base classes that cannot be instantiated directly.
  • Python doesn't have a separate interface keyword — abstract base classes and "duck typing" (informal protocols) serve this purpose.

5.5 Inheritance

A mechanism where a class (subclass) derives attributes/methods from another class (superclass).

class Animal:
    def speak(self):
        print("Some sound")

class Dog(Animal):          # single inheritance
    def speak(self):
        print("Bark")

class Hybrid(Dog, Animal):  # multiple inheritance is allowed
    pass
  • Python supports multiple inheritance directly, resolved via the C3 linearization / MRO (Method Resolution Order), viewable with ClassName.__mro__.
  • super() is used to call the parent class's methods/constructor.

5.6 Polymorphism

The ability for different classes/objects to be treated through a common interface, with behavior depending on actual object type.

class Cat:
    def speak(self): return "Meow"
class Dog:
    def speak(self): return "Woof"

for animal in [Cat(), Dog()]:
    print(animal.speak())    # duck typing — no common base class required
  • Python achieves polymorphism primarily through duck typing: "If it walks like a duck and quacks like a duck, it's a duck" — no explicit inheritance/interface is required, just matching method names.
  • Operator overloading is done via dunder (magic) methods like __add__, __str__, __len__, etc.
  • No compile-time (static) polymorphism/overloading by signature — Python resolves purely at runtime.

5.7 Constructors

A special method that initializes a newly created object.

class Point:
    def __init__(self, x=0, y=0):   # constructor / initializer
        self.x = x
        self.y = y

    def __new__(cls, *args, **kwargs):   # actual object creator (rarely overridden)
        return super().__new__(cls)
  • __init__ is technically the initializer, not the true constructor — __new__ is the actual object-creating method (called before __init__), but __init__ is what developers typically call "the constructor."
  • Python has no constructor overloading; default arguments or classmethod factory functions are used to simulate multiple constructors.
  • No explicit destructor is normally needed; __del__ exists but its call timing is not guaranteed (depends on garbage collection).

066. Exception Handling

6.1 Exceptions

An exception is an event that disrupts normal program flow, typically due to an error, represented as an object in Python.

try:
    x = 10 / 0
except ZeroDivisionError as e:
    print("Error:", e)
  • All exceptions inherit from the BaseException class (with Exception being the base for almost all user-relevant errors).
  • Python exceptions are unchecked — the compiler/interpreter does not force you to declare or catch them (similar to C++, unlike Java's checked exceptions).

6.2 Handling

try:
    risky_operation()
except (ValueError, TypeError) as e:   # multiple exception types
    print("Handled:", e)
except Exception as e:
    print("Generic handler:", e)
else:
    print("Runs if no exception occurred")
finally:
    print("Always runs — cleanup code")
  • try / except / else / finally blocks. The else clause (unique emphasis in Python, though Java/C++ don't have a direct parallel) runs only if no exception was raised.
  • finally always executes, used for cleanup (closing files, releasing resources), similar to Java/C++.
  • Custom exceptions are created by subclassing Exception.
class InsufficientFundsError(Exception):
    pass

raise InsufficientFundsError("Balance too low")

6.3 Propagation

If an exception is not caught in the current function, it propagates up the call stack to the caller, and further up, until caught or the program terminates with a traceback.

def a(): b()
def b(): c()
def c(): raise ValueError("deep error")

try:
    a()
except ValueError as e:
    print("Caught at top level:", e)   # exception propagated up 3 frames
  • Python shows a full traceback listing every frame the exception passed through.
  • raise (bare) inside an except block re-raises the current exception, preserving the original traceback.
  • raise NewError from original_error allows exception chaining, explicitly showing the causal exception.
