011. Programming Fundamentals

1.1 Variables

A variable is a named reference to a memory location that stores a value. In Python, a variable is created the moment you assign a value to it — there is no separate declaration step.

x = 10          # x is bound to an integer object
name = "Alice"  # name is bound to a string object
x = "now text"  # x can be rebound to a different type

Key ideas:

  • Python variables are names bound to objects, not fixed memory boxes with a type. The name x is just a label pointing to whatever object is currently assigned.
  • Multiple names can point to the same object (aliasing): a = [1,2]; b = a — both a and b refer to the same list.
  • Variable naming rules: must start with a letter or underscore, can contain letters/digits/underscores, case-sensitive, cannot be a reserved keyword.
  • Python uses dynamic typing — the type is attached to the object, not the variable name, so the same name can be reassigned to any type.
  • Variables in Python are created at first assignment and destroyed by garbage collection when no references remain (reference counting + cycle detector).

Java

In Java, every variable must be declared with an explicit type before use, and that type cannot change afterward. Java distinguishes primitive variables (int, double, char, boolean, etc.), which store their value directly, from reference variables, which hold a reference to an object on the heap. Local variables get no default value and must be initialized before use; instance/class fields are automatically defaulted (0, false, null).

int x = 10;             // primitive - holds the value directly
String name = "Alice";  // reference - points to a String object on the heap
x = 20;                 // fine - same type
// x = "text";          // COMPILE ERROR - type mismatch

C

In C, a variable is a named region of memory whose type is fixed at declaration and determines how the bytes there are interpreted. There is no runtime type information — the compiler enforces (and sometimes silently coerces) types at compile time. Uninitialized local variables contain garbage, so C offers no safety net against reading them before assignment.

int x = 10;      /* 4 bytes, interpreted as a signed integer */
char name[20];   /* fixed-size char array - C has no built-in string type */
int y;           /* uninitialized - garbage value until assigned */

C++

C++ variables work like C's at the core (fixed type, direct memory storage) but add stronger typing, constructors for class-type variables, references, and compile-time type inference via auto. A variable of class type automatically runs its constructor when it comes into scope and its destructor when it goes out of scope (RAII).

int x = 10;
auto y = 3.14;                 // type inferred as double at compile time
std::string name = "Alice";    // class-type variable - constructor runs automatically
int &ref = x;                  // reference: an alias for x, not a new variable

1.2 Data Types

Python's built-in data types are grouped into: numeric (int, float, complex), sequence (str, list, tuple, range), mapping (dict), set types (set, frozenset), boolean (bool), and NoneType.

i = 10            # int  (arbitrary precision)
f = 3.14          # float (double precision)
c = 2 + 3j        # complex
s = "hello"       # str (immutable sequence of Unicode chars)
lst = [1, 2, 3]   # list (mutable, ordered)
tup = (1, 2, 3)   # tuple (immutable, ordered)
d = {"a": 1}      # dict (mutable key-value mapping)
st = {1, 2, 3}    # set (mutable, unordered, unique elements)
b = True          # bool
n = None          # NoneType
  • Python is dynamically and strongly typed: types aren't declared, but implicit unsafe coercions (like "2" + 2) raise errors rather than silently converting.
  • int in Python has arbitrary precision (no overflow, limited only by memory).
  • type() returns an object's type at runtime; isinstance() checks type membership including subclasses.
  • Everything in Python — including functions, classes, and modules — is an object.

Java

Java has eight built-in primitive types (byte, short, int, long, float, double, char, boolean) with fixed, platform-independent sizes, plus corresponding wrapper classes (Integer, Double, ...) that let primitives be used as objects — for example inside collections. Everything else (arrays, String, custom classes) is a reference type.

int i = 10;
double d = 3.14;
boolean flag = true;
Integer boxed = 10;   // autoboxing: primitive wrapped as an object

C

C's type system is minimal: basic numeric types (int, float, double, char), each with a size that can vary by platform/compiler, plus derived types built from them — arrays, pointers, structs, unions. There is no built-in string, and no boolean type before C99's stdbool.h.

int i = 10;
float f = 3.14f;
char c = 'A';
struct Point { int x, y; };   /* user-defined aggregate type */

C++

C++ keeps all of C's primitive types, adds bool, and layers on a large standard library of class types (std::string, std::vector, ...) that behave like built-in types but manage their own memory. Templates additionally allow generic types parameterized over any type.

int i = 10;
bool flag = true;
std::string s = "hello";
std::vector<int> nums = {1, 2, 3};

1.3 Operators

Python supports arithmetic, relational, logical, bitwise, assignment, identity, and membership operators.

7 // 2      # 3   → floor division
7 % 2       # 1   → modulo
2 ** 3      # 8   → exponentiation
5 == 5.0    # True → value equality
a is b      # identity comparison (same object in memory)
3 in [1,2,3]# True → membership test
True and False  # logical AND (returns operand, not just bool)
  • // floor division and ** exponentiation are unique operators not directly available (as symbols) in C/C++/Java.
  • and, or, not are keyword-based logical operators (not &&, ||, !), and they perform short-circuit evaluation returning the actual operand, not just True/False.
  • is compares object identity (memory address); == compares value equality. This distinction is unique in emphasis to Python.
  • in / not in are membership operators for sequences and collections.
  • No ++ or -- operators in Python.

Java

Java's operator set closely mirrors C/C++ (arithmetic, relational, logical &&/||/!, bitwise, ++/--), but integer division and overflow behavior are strictly defined by the language specification regardless of platform. Java has no user-defined operator overloading — the only exception baked into the language is + for String concatenation.

int a = 7 / 2;       // 3 - integer division truncates toward zero
double b = 7.0 / 2;  // 3.5
boolean r = (a > 0) && (b > 0);  // short-circuit AND

C

C's operators are close to the metal: arithmetic, relational, logical, bitwise, and pointer operators (*, &, ->) for direct memory manipulation. Integer division truncates toward zero, and signed integer overflow is undefined behavior — a notorious source of subtle bugs.

int a = 7 / 2;    /* 3 */
int *p = &a;      /* & takes the address of a */
int b = *p + 1;   /* * dereferences the pointer */

C++

C++ inherits all of C's operators and adds operator overloading, letting user-defined types define custom behavior for +, ==, <<, and more. It also adds reference-related operators and the scope-resolution operator ::.

struct Vec2 {
    double x, y;
    Vec2 operator+(const Vec2 &o) const { return {x + o.x, y + o.y}; }
};
Vec2 a{1, 2}, b{3, 4};
Vec2 c = a + b;   // calls the overloaded operator+

1.4 Expressions

An expression is any valid combination of values, variables, operators, and function calls that evaluates to a value.

result = (a + b) * c - d / 2
is_valid = (x > 0) and (x < 100)
squares = [i**2 for i in range(10)]   # list comprehension is an expression
value = x if x > 0 else -x            # conditional (ternary) expression
  • Python supports list/dict/set/generator comprehensions as compact expressions — a feature not natively present in C/C++/Java.
  • The ternary conditional expression syntax is value_if_true if condition else value_if_false (unlike C/Java/C++'s condition ? true_val : false_val).
  • Expressions can be chained: 1 < x < 10 is valid Python (equivalent to 1 < x and x < 10), which is not valid in C/C++/Java.

Java

Java expressions follow standard operator precedence and evaluate to a typed value; the ternary operator cond ? a : b is the closest thing to a compact conditional expression. Java has no expression-based comprehensions — the nearest equivalent is chaining Stream operations.

int max = (a > b) ? a : b;
List<Integer> squares = nums.stream().map(n -> n * n).collect(Collectors.toList());

C

C expressions are strictly value-producing combinations of operators and operands; there is no comprehension or collection-building expression syntax. The comma operator and ternary ?: are available, and pointer arithmetic is a distinctly C-flavored expression form.

int max = (a > b) ? a : b;
int *next = p + 1;   /* pointer arithmetic: address of the next int */

C++

C++ expressions include everything C offers, plus operator-overload-driven expressions and lambda expressions. Since C++20, ranges approximate some comprehension-like composition, though nothing as compact as Python's list comprehensions.

int max = (a > b) ? a : b;
auto square = [](int n){ return n * n; };

1.5 Statements

A statement is an instruction that performs an action (assignment, control flow, import, etc.), as opposed to an expression which produces a value.

x = 5                  # assignment statement
if x > 0:               # compound statement
    print("positive")
import math             # import statement
def greet(): pass       # function definition statement
  • Python uses indentation to define statement blocks instead of braces {}.
  • Statements typically end with a newline; no semicolon required (though ; can separate multiple statements on one line).
  • Compound statements (if, for, while, def, class) always end with a colon :.

Java

Java statements are terminated with a semicolon and grouped into blocks with braces. Every statement, including a single line of logic, must live inside a class body — there is no free-floating top-level code as in Python or C.

public class Main {
    public static void main(String[] args) {
        int x = 5;                        // statement
        if (x > 0) { System.out.println("positive"); }
    }
}

C

C statements are semicolon-terminated and block-scoped by braces, executed top-to-bottom inside functions. Program execution always starts at main().

int main(void) {
    int x = 5;
    if (x > 0) { printf("positive\n"); }
    return 0;
}

C++

C++ statement syntax matches C's, but declarations can appear anywhere in a block (not just at the top, as older C required), and statements can trigger construction/destruction side effects tied to scope.

int main() {
    int x = 5;
    if (x > 0) { std::cout << "positive\n"; }
}

022. Program Control

2.1 if / else

if x > 0:
    print("positive")
elif x == 0:
    print("zero")
else:
    print("negative")
  • Python's elif combines "else if" into a single keyword.
  • No parentheses required around the condition, but a colon : and indentation are mandatory.
  • Python has no switch statement in the traditional sense before 3.10; instead match-case (structural pattern matching) was added in Python 3.10.

Java

Java's if/else requires parentheses around the condition and braces (optional for a single statement) for the block. The condition must be a genuine boolean expression — unlike C, an int cannot be used directly as a condition.

if (x > 0) {
    System.out.println("positive");
} else if (x == 0) {
    System.out.println("zero");
} else {
    System.out.println("negative");
}

C

C's if/else uses the same structure, but the condition can be any integral expression — zero is treated as false and any non-zero value as true, a common source of bugs (e.g. if (x = 5) compiles and is always true).

if (x > 0) {
    printf("positive\n");
} else if (x == 0) {
    printf("zero\n");
} else {
    printf("negative\n");
}

C++

C++'s if/else works like C's, but additionally allows a variable to be declared and initialized directly inside the condition (C++17), scoping it to both branches.

if (int y = compute(); y > 0) {
    std::cout << "positive: " << y << "\n";
} else {
    std::cout << "not positive\n";
}

2.2 switch

Python did not have a switch statement until match-case was introduced in Python 3.10 (structural pattern matching).

match command:
    case "start":
        print("Starting")
    case "stop":
        print("Stopping")
    case _:
        print("Unknown command")
  • match-case supports pattern matching (destructuring tuples, matching types, guards with if), which is more powerful than a plain C-style switch.
  • Prior to 3.10, developers simulated switch behavior using if-elif chains or dictionaries mapping values to functions.

Java

Java's switch works on int, char, String, and enum values, and falls through to the next case unless a break is used. Java 14+ also added an enhanced switch expression (switch -> {}) that returns a value and doesn't fall through.

switch (day) {
    case "MON": System.out.println("Start of week"); break;
    case "FRI": System.out.println("Almost weekend"); break;
    default: System.out.println("Midweek");
}

C

C's switch works only on integral/enum types (not strings), typically compiled to a jump table for fast dispatch, and falls through by default unless each case ends in break.

switch (grade) {
    case 'A': printf("Excellent\n"); break;
    case 'B': printf("Good\n"); break;
    default: printf("Needs work\n");
}

C++

C++'s switch behaves like C's (integral/enum types only, fallthrough by default), but also supports the [[fallthrough]] attribute (C++17) to explicitly document intentional fallthrough and silence compiler warnings.

switch (grade) {
    case 'A': std::cout << "Excellent\n"; break;
    case 'B': [[fallthrough]];
    case 'C': std::cout << "Passing\n"; break;
    default: std::cout << "Needs work\n";
}

2.3 loops

Python has two loop constructs: for (iterates over a sequence/iterable) and while (repeats while a condition holds).

for i in range(5):        # iterates 0..4
    print(i)

for item in [10, 20, 30]:  # iterates over any iterable
    print(item)

i = 0
while i < 5:
    print(i)
    i += 1

for i in range(5):
    else:                  # NOTE: for-else — runs if loop completes without break
        ...
  • Python's for loop is fundamentally iterator-based: it works over anything implementing the iterator protocol (__iter__/__next__), not a numeric counter like C.
  • Python uniquely supports for...else and while...else: the else block executes only if the loop finishes without hitting a break.
  • There is no traditional C-style for(init; cond; incr) loop in Python — you emulate it with range().

Java

Java supports the classic for(init;cond;incr), while, do-while, and an enhanced for-each loop for arrays/collections. There is no loop-else construct.

for (int i = 0; i < 5; i++) { System.out.println(i); }
for (int n : new int[]{10, 20, 30}) { System.out.println(n); }
int i = 0;
do { System.out.println(i); i++; } while (i < 5);

C

C only has the classic three-clause for, while, and do-while loops — there is no enhanced for-loop, so iterating an array always means manual indexing.

for (int i = 0; i < 5; i++) { printf("%d\n", i); }
int i = 0;
do { printf("%d\n", i); i++; } while (i < 5);

C++

C++ has everything C has, plus a range-based for loop (C++11) that iterates containers/arrays directly without manual indexing — closer in spirit to Python's for...in.

for (int i = 0; i < 5; i++) { std::cout << i << "\n"; }
std::vector<int> nums = {10, 20, 30};
for (int n : nums) { std::cout << n << "\n"; }

2.4 break / continue

for i in range(10):
    if i == 5:
        break       # exits the loop entirely
    if i % 2 == 0:
        continue    # skips to next iteration
    print(i)
  • Behave the same conceptually as in C/C++/Java: break exits the nearest enclosing loop, continue skips to the next iteration.
  • Python has no labeled break/continue (unlike Java), so breaking out of nested loops requires flags, exceptions, or refactoring into functions.

Java

Java's break and continue work as in C/C++, but Java uniquely supports labeled break/continue, letting you exit or skip an outer loop directly from inside a nested loop.

outer:
for (int i = 0; i < 3; i++) {
    for (int j = 0; j < 3; j++) {
        if (j == 1) continue outer;
        if (i == 2) break outer;
        System.out.println(i + "," + j);
    }
}

C

C has break and continue but no labels for them — breaking out of nested loops requires a flag variable or a goto to a label placed after the loops.

for (int i = 0; i < 3; i++) {
    for (int j = 0; j < 3; j++) {
        if (i == 2) goto done;   /* simulate breaking out of both loops */
    }
}
done: ;

C++

C++'s break/continue behave exactly like C's — no labeled loop control — though goto remains available for the same nested-break workaround, generally discouraged in favor of restructuring into a function with an early return.

for (int i = 0; i < 3; i++) {
    for (int j = 0; j < 3; j++) {
        if (j == 1) continue;
        if (i == 2) goto done;
    }
}
done: ;

2.5 recursion

A function calling itself directly or indirectly to solve smaller subproblems until a base case is reached.

def factorial(n):
    if n <= 1:          # base case
        return 1
    return n * factorial(n - 1)   # recursive case
  • Python has a default recursion limit (typically 1000, adjustable via sys.setrecursionlimit()), because CPython does not implement tail-call optimization — deep recursion can raise RecursionError.
  • Every recursive call adds a new stack frame in Python's call stack, same conceptual model as C/C++/Java, but Python's limit is much lower and configurable in software rather than being purely OS-stack-size-bound.

Java

Java recursion works the same conceptually as elsewhere, but each call consumes a JVM stack frame, bounded by the thread's stack size (adjustable with -Xss). Exceeding it throws a catchable StackOverflowError.

static int factorial(int n) {
    if (n <= 1) return 1;
    return n * factorial(n - 1);
}

C

C recursion is bounded by the OS-allocated call stack; there is no runtime check, so exceeding it typically crashes the program (segmentation fault) rather than raising a catchable error.

int factorial(int n) {
    if (n <= 1) return 1;
    return n * factorial(n - 1);
}

C++

C++ recursion behaves like C's (OS stack-bound, crash on overflow rather than an exception), though well-optimizing compilers may apply tail-call optimization for simple tail-recursive functions at high optimization levels.

int factorial(int n) {
    if (n <= 1) return 1;
    return n * factorial(n - 1);
}

033. Functions & Scope

3.1 Functions / Methods

def add(a, b=10):        # default parameter value
    return a + b

def variadic(*args, **kwargs):   # variable-length positional and keyword args
    print(args, kwargs)

square = lambda x: x * x         # anonymous function
  • Defined with def; functions are first-class objects — can be assigned to variables, passed as arguments, returned from other functions, and stored in data structures.
  • Support default arguments, keyword arguments, arbitrary positional (*args) and keyword (**kwargs) arguments, and lambda (anonymous) functions.
  • A "method" is simply a function defined inside a class; it implicitly receives the instance as its first parameter (self).
  • No function overloading by signature (Python resolves by the single most recent def with that name); default/variadic args are used to simulate it.

Java

Every function in Java must be a method of some class — there are no free-floating functions. Java supports method overloading (same name, different parameter lists) resolved at compile time, but not default parameter values; variadic arguments are supported through ... varargs.

static int add(int a, int b) { return a + b; }
static double add(double a, double b) { return a + b; }   // overload
static int sum(int... nums) { int t = 0; for (int n : nums) t += n; return t; }

C

C functions are standalone, declared with a fixed return type and parameter list. C has no overloading, no default arguments, and no nested functions (standard C) — variable-length argument lists are possible only through the low-level stdarg.h macros.

int add(int a, int b) { return a + b; }
#include <stdarg.h>
int sum(int count, ...) {
    va_list args; va_start(args, count);
    int total = 0;
    for (int i = 0; i < count; i++) total += va_arg(args, int);
    va_end(args);
    return total;
}

C++

C++ functions can exist outside classes (like C) or as class methods, support overloading and default argument values, and offer variadic templates for type-safe variable-length argument lists — a much safer alternative to C's stdarg.h.

int add(int a, int b) { return a + b; }
int add(int a, int b, int c) { return a + b + c; }   // overload
int greet(std::string name, std::string greeting = "Hello") {
    std::cout << greeting << ", " << name << "\n"; return 0;
}

3.2 Scope

Python scoping follows the LEGB rule: Local → Enclosing → Global → Built-in.

x = "global"

def outer():
    x = "enclosing"
    def inner():
        nonlocal x       # refers to enclosing scope's x
        x = "modified"
    inner()
    print(x)              # "modified"

def f():
    global x
    x = "changed globally"
  • Local scope: names assigned inside a function.
  • Enclosing scope: names in the local scope of any enclosing function (closures).
  • Global scope: names assigned at the top level of a module.
  • Built-in scope: names preassigned by Python (len, print, etc.).
  • Unlike C/Java/C++, Python does not create a new scope for blocks like if, for, while — only functions (and classes, partially) create new scopes.
  • global and nonlocal keywords are required to modify variables from outer scopes inside a function.

Java

Java is block-scoped like C/C++: every {} (including if/for/while bodies) introduces a new scope, and a local variable cannot be accessed outside the block it's declared in. Fields declared in a class are accessible throughout the class regardless of method order.

if (true) {
    int x = 5;   // scoped to this block only
}
// x is not visible here

C

C is strictly block-scoped; a variable declared inside {} is invisible outside it. Traditional C (pre-C99) also required all declarations at the top of a block, though modern C relaxes this.

{
    int x = 5;   /* scoped to this block */
}
/* x is not visible here */

C++

C++ scoping matches C's block scoping, plus namespace scope for grouping names to avoid collisions, and class scope for members. Lambda captures also introduce their own controlled access to enclosing-scope variables.

namespace mathutils { int square(int x) { return x * x; } }
int y = mathutils::square(4);

3.3 Lifetime

Lifetime refers to how long an object/variable exists in memory.

  • Python objects live as long as there is at least one reference to them (reference counting), plus a cyclic garbage collector to clean up reference cycles.
  • Local variables' *bindings* die when the function returns, but the *objects* they reference may persist if referenced elsewhere (e.g., returned, or captured by a closure).
  • Global variables live for the duration of the program (module's lifetime).

Java

Object lifetime in Java is managed entirely by the JVM's garbage collector — an object stays alive as long as it's reachable from a GC root, and is reclaimed at some non-deterministic point after becoming unreachable. Local primitive variables live only for the duration of their enclosing block/method call.

void makeList() {
    List<Integer> list = new ArrayList<>();  // lives as long as it's referenced
}  // if nothing else references it, eligible for GC after this returns

C

C has no automatic memory management: a local (automatic) variable's lifetime ends when its block exits, while heap memory from malloc() lives until explicitly freed with free() — forgetting to do so is a memory leak, and using it after freeing is a dangling-pointer bug.

int *p = malloc(sizeof(int));
*p = 10;
free(p);       /* memory released - must not use *p after this */

C++

C++ combines C's manual heap lifetime with RAII: stack-allocated objects have deterministic lifetime tied to scope, automatically calling their destructor at scope exit, and smart pointers (unique_ptr, shared_ptr) extend that determinism to heap objects, largely eliminating manual free/delete.

{
    std::unique_ptr<int> p = std::make_unique<int>(10);
}  // p's destructor runs here automatically, freeing the memory

3.4 Parameter Passing

Python uses "pass by object reference" (also called "pass by assignment"): the function receives a reference to the same object, but rebinding the parameter name inside the function does not affect the caller's variable. However, mutating a mutable object (like a list) *does* affect the caller.

def modify_list(lst):
    lst.append(4)      # mutates the shared object — visible outside

def reassign(lst):
    lst = [100]         # rebinds local name only — NOT visible outside

nums = [1, 2, 3]
modify_list(nums)   # nums is now [1, 2, 3, 4]
reassign(nums)       # nums is still [1, 2, 3, 4]

Java

Java always passes arguments by value: for primitives, the value itself is copied; for objects, the reference (pointer to the object) is copied — so mutating the object's fields inside a method is visible to the caller, but reassigning the parameter to a new object is not.

void modify(List<Integer> list) { list.add(4); }               // visible to caller
void reassign(List<Integer> list) { list = new ArrayList<>(); } // not visible

C

C passes everything strictly by value, including pointers — a function receives a copy of whatever was passed. To let a function modify the caller's variable, the caller must explicitly pass a pointer to it.

void increment(int *x) { (*x)++; }  /* must pass &variable to affect the caller */
int n = 5;
increment(&n);   /* n is now 6 */

C++

C++ supports everything C does, plus true reference parameters (Type&), which let a function modify the caller's variable directly without pointer syntax, and const references, which avoid copying large objects while preventing modification.

void increment(int &x) { x++; }   // no pointer syntax needed
int n = 5;
increment(n);   // n is now 6

3.5 Binding

Binding refers to associating a name with an object/value, and *when* that association happens.

  • Python is dynamically bound / late-bound: names are resolved at runtime, not compile time. A name lookup happens each time the code executes.
  • Function/method calls in Python are resolved dynamically (duck typing) — there's no need for explicit interfaces for polymorphism.
  • Variable rebinding is simply reassignment: x = x + 1 creates a new binding for x (doesn't mutate the old int object, since ints are immutable).

Java

Java uses static binding for fields, static methods, and overloaded methods (resolved at compile time by declared type), but dynamic (virtual) binding for overridden instance methods — the JVM decides at runtime which override to call based on the object's actual class.

class Animal { void speak(){ System.out.println("..."); } }
class Dog extends Animal { void speak(){ System.out.println("Bark"); } }
Animal a = new Dog();
a.speak();   // "Bark" - resolved dynamically based on actual type

C

C has no polymorphism or dynamic dispatch built into the language; function calls are always statically bound at compile time to the exact function named. Function pointers can simulate dynamic dispatch manually.

void (*speak)(void) = dog_speak;  /* manual "dynamic dispatch" via function pointer */
speak();

C++

C++ uses static binding by default (including for overloaded functions), but a method marked virtual in a base class enables dynamic binding through pointers/references to that base, resolved at runtime via a vtable — the mechanism Java's dynamic dispatch is modeled after.

struct Animal { virtual void speak(){ std::cout << "...\n"; } };
struct Dog : Animal { void speak() override { std::cout << "Bark\n"; } };
Animal *a = new Dog();
a->speak();   // "Bark" - dynamic binding via virtual

044. Programming Paradigms

4.1 Imperative Programming

Programming by giving the computer a sequence of explicit statements that change program state (variables) step by step.

total = 0
for n in range(1, 6):
    total += n
print(total)   # imperative: explicit steps mutate 'total'

Python fully supports imperative style — it's the default/most common style used for scripts, loops, and object mutation.

4.2 Functional Programming

Programming built around pure functions, immutability, and function composition rather than mutable state.

nums = [1, 2, 3, 4, 5]
squares = list(map(lambda x: x**2, nums))
evens = list(filter(lambda x: x % 2 == 0, nums))
from functools import reduce
total = reduce(lambda a, b: a + b, nums)
squares_comp = [x**2 for x in nums]   # more "Pythonic" functional-style alternative
  • Python supports functional tools: map(), filter(), reduce(), lambda, first-class functions, and comprehensions.
  • Python is not purely functional — it allows mutable state, side effects, and doesn't enforce immutability or referential transparency.

4.3 Logic Programming

A declarative paradigm where the programmer states *facts and rules*, and the system infers answers via logical inference (e.g., Prolog).

  • Python has no native logic-programming paradigm, but it can be simulated using libraries such as kanren (miniKanren-based) or by writing constraint-solvers manually, or using Prolog-interfacing libraries like pyswip.
  • Python's pattern-matching (match-case) and constraint libraries approximate some declarative-style logic but it is not a true logic-programming language.

Java

Java code is imperative by default — explicit statements, loops, and mutable variables driving state changes, wrapped in an object-oriented structure.

int total = 0;
for (int n = 1; n <= 5; n++) { total += n; }

C

C is a purely imperative/procedural language — there is no built-in object system or functional abstraction, just sequences of statements operating on data.

int total = 0;
for (int n = 1; n <= 5; n++) { total += n; }

C++

C++ supports imperative style fully (inherited from C) and layers OOP and generic programming on top, but plain procedural, statement-driven code remains completely valid and common.

int total = 0;
for (int n = 1; n <= 5; n++) { total += n; }

Java

Since Java 8, functional-style programming is supported through lambda expressions, functional interfaces (Runnable, Function<T,R>, ...), and the Streams API, which offers map/filter/reduce-style pipelines over collections.

List<Integer> squares = nums.stream()
    .map(n -> n * n)
    .filter(n -> n % 2 == 0)
    .collect(Collectors.toList());

C

C has no native functional programming support — no lambdas (pre-C23), no first-class functions beyond function pointers, and no built-in map/filter/reduce; these must be hand-rolled with loops and function pointers.

int apply(int (*fn)(int), int x) { return fn(x); }
int square(int x) { return x * x; }
int result = apply(square, 5);

C++

C++11 onward adds lambda expressions, std::function for storing callables, and <algorithm> functions like std::transform, std::copy_if, and std::accumulate that mirror map/filter/reduce.

std::vector<int> squares;
std::transform(nums.begin(), nums.end(), std::back_inserter(squares),
               [](int n){ return n * n; });

Java

Java has no native logic-programming paradigm; declarative, rule-based logic is typically achieved through external rule engines (e.g. Drools) rather than language features.

C

C has no native logic-programming support either; anything rule- or inference-based must be built entirely from scratch using data structures and search algorithms.

C++

C++ likewise has no built-in logic-programming paradigm, though its template metaprogramming system is (perhaps surprisingly) Turing-complete and can express certain compile-time logical deductions — more a curiosity than a practical logic-programming tool.

055. Object-Oriented Programming (OOP)

5.1 Class

A class is a blueprint that defines attributes (data) and methods (behavior) for creating objects.

class Car:
    wheels = 4                 # class attribute (shared)

    def __init__(self, brand):  # constructor
        self.brand = brand      # instance attribute

    def drive(self):
        print(f"{self.brand} is driving")

Java

A class in Java is declared with class, and for a public class the file name must match the class name. Every method belongs to a class — Java has no way to define a function outside one.

public class Car {
    static int wheels = 4;      // class (static) field - shared by all instances
    String brand;                // instance field
    Car(String brand) { this.brand = brand; }   // constructor
    void drive() { System.out.println(brand + " is driving"); }
}

C

C has no classes — the closest equivalent is a struct, which bundles data fields together but cannot hold methods; behavior must be implemented as separate functions that take a pointer to the struct.

struct Car { char brand[20]; };
void drive(struct Car *c) { printf("%s is driving\n", c->brand); }

C++

C++ classes work like Java's conceptually, but multiple classes can live in one file freely, and a class's members default to private (unlike struct, whose members default to public) — the two keywords are otherwise interchangeable.

class Car {
public:
    Car(std::string brand) : brand(brand) {}
    void drive() { std::cout << brand << " is driving\n"; }
private:
    std::string brand;
};

5.2 Object

An object is an instance of a class — a concrete entity with actual attribute values in memory.

my_car = Car("Toyota")   # my_car is an object/instance of Car
my_car.drive()

Every Python value — even integers and functions — is technically an object of some class, unlike C++/Java where primitives are not objects.

5.3 Encapsulation

Bundling data and methods together and restricting direct access to some of an object's components.

class Account:
    def __init__(self, balance):
        self._balance = balance    # "protected" by convention (single underscore)
        self.__pin = "1234"        # "private" via name mangling (double underscore)

    def get_balance(self):
        return self._balance
  • Python has no true access modifiers (private/protected/public) enforced by the language. It relies on naming conventions:
  • _name → convention for "protected" (internal use), not enforced.
  • __name → triggers name mangling (_ClassName__name), making accidental access harder but still not truly private.
  • Properties (@property decorator) provide getter/setter-like encapsulation with clean syntax.

Java

An object in Java is created with new, which allocates it on the heap and returns a reference to it. All Java objects live on the heap and are accessed only through references, never directly by value.

Car myCar = new Car("Toyota");
myCar.drive();

C

C has no object concept — only struct instances, which can live on the stack or heap (via malloc) and are manipulated directly or through pointers, with no inherent behavior attached.

struct Car myCar = { "Toyota" };
drive(&myCar);

C++

C++ objects can live on the stack (automatic, destroyed at scope end) or the heap (via new, requiring explicit delete or a smart pointer), giving more control over object lifetime than Java's heap-only model.

Car myCar("Toyota");               // stack object
myCar.drive();
Car *heapCar = new Car("Honda");   // heap object - needs delete

Java

Java enforces true access control with private, protected, public, and default (package-private) modifiers, checked at compile time — a private field genuinely cannot be accessed from outside its class.

public class Account {
    private double balance;
    public double getBalance() { return balance; }
}

C

C has no access control at the language level — all struct fields are always accessible from anywhere the struct type is visible. Encapsulation is only achievable by convention, e.g. exposing only functions in a header and hiding the struct definition in a .c file.

/* account.h exposes only function declarations, hiding the struct's fields in account.c */
typedef struct Account Account;
double get_balance(Account *a);

C++

C++ enforces access control like Java, with private, protected, and public sections checked at compile time, giving true encapsulation unlike Python's convention-only approach.

class Account {
private:
    double balance;
public:
    double getBalance() const { return balance; }
};

5.4 Abstraction

Hiding complex implementation details and exposing only essential features via a simplified interface.

from abc import ABC, abstractmethod

class Shape(ABC):
    @abstractmethod
    def area(self):
        pass          # must be implemented by subclasses

class Circle(Shape):
    def __init__(self, r):
        self.r = r
    def area(self):
        return 3.14 * self.r ** 2
  • Achieved via the abc module (ABC, @abstractmethod) to define abstract base classes that cannot be instantiated directly.
  • Python doesn't have a separate interface keyword — abstract base classes and "duck typing" (informal protocols) serve this purpose.

Java

Java provides two abstraction mechanisms: abstract class (can have partial implementation) and interface (traditionally pure method signatures, though default methods are allowed since Java 8). A class can implement multiple interfaces even though it can extend only one class.

interface Shape { double area(); }
class Circle implements Shape {
    double r;
    Circle(double r) { this.r = r; }
    public double area() { return Math.PI * r * r; }
}

C

C has no abstract types; the closest approximation is a struct of function pointers acting as a manually built "interface", which calling code fills in with concrete function implementations.

typedef struct { double (*area)(void *self); } ShapeVTable;

C++

C++ creates an abstract class via pure virtual functions (= 0); a class with even one pure virtual function cannot be instantiated directly. A class made entirely of pure virtual functions plays the role of Java's interface.

class Shape { public: virtual double area() const = 0; };
class Circle : public Shape {
    double r;
public:
    Circle(double r) : r(r) {}
    double area() const override { return 3.14159 * r * r; }
};

5.5 Inheritance

A mechanism where a class (subclass) derives attributes/methods from another class (superclass).

class Animal:
    def speak(self):
        print("Some sound")

class Dog(Animal):          # single inheritance
    def speak(self):
        print("Bark")

class Hybrid(Dog, Animal):  # multiple inheritance is allowed
    pass
  • Python supports multiple inheritance directly, resolved via the C3 linearization / MRO (Method Resolution Order), viewable with ClassName.__mro__.
  • super() is used to call the parent class's methods/constructor.

Java

Java supports single inheritance of classes only (extends), avoiding the diamond problem entirely, but a class can implement multiple interfaces to gain multiple type contracts.

class Animal { void speak(){ System.out.println("..."); } }
class Dog extends Animal {
    @Override void speak(){ System.out.println("Bark"); }
}

C

C has no inheritance mechanism; a similar effect is sometimes approximated by embedding one struct as the first field of another ("struct composition"), though this gives no automatic behavior sharing.

struct Animal { char name[20]; };
struct Dog { struct Animal base; };   /* manual "inheritance" by composition */

C++

C++ supports multiple inheritance directly, which can create the diamond problem if two base classes share a common ancestor — resolved explicitly with virtual inheritance on the shared base.

class Animal { public: void speak(){ std::cout << "...\n"; } };
class Dog : public Animal {
public: void speak(){ std::cout << "Bark\n"; }
};

5.6 Polymorphism

The ability for different classes/objects to be treated through a common interface, with behavior depending on actual object type.

class Cat:
    def speak(self): return "Meow"
class Dog:
    def speak(self): return "Woof"

  • Python achieves polymorphism primarily through duck typing: "If it walks like a duck and quacks like a duck, it's a duck" — no explicit inheritance/interface is required, just matching method names.
  • Operator overloading is done via dunder (magic) methods like __add__, __str__, __len__, etc.
  • No compile-time (static) polymorphism/overloading by signature — Python resolves purely at runtime.

Java

Java achieves polymorphism through inheritance/interfaces combined with method overriding — all non-static, non-final instance methods are virtual (dynamically dispatched) by default, unlike C++ where you must opt in with virtual.

List<Animal> animals = List.of(new Dog(), new Cat());
for (Animal a : animals) a.speak();   // calls the correct override for each

C

C has no polymorphism built in; it can be simulated manually using structs of function pointers, where each "type" fills in its own function implementations — the technique C++'s vtables are modeled after.

typedef struct { void (*speak)(void); } Animal;

C++

struct Animal { virtual void speak(){ std::cout << "...\n"; } };
struct Dog : Animal { void speak() override { std::cout << "Bark\n"; } };

5.7 Constructors

A special method that initializes a newly created object.

class Point:
    def __init__(self, x=0, y=0):   # constructor / initializer
        self.x = x
        self.y = y

    def __new__(cls, *args, **kwargs):   # actual object creator (rarely overridden)
        return super().__new__(cls)
  • __init__ is technically the initializer, not the true constructor — __new__ is the actual object-creating method (called before __init__), but __init__ is what developers typically call "the constructor."
  • Python has no constructor overloading; default arguments or classmethod factory functions are used to simulate multiple constructors.
  • No explicit destructor is normally needed; __del__ exists but its call timing is not guaranteed (depends on garbage collection).

Java

A Java constructor shares the class's name and has no return type. Java supports constructor overloading (multiple constructors with different parameter lists), and this(...) can call another constructor in the same class.

class Point {
    int x, y;
    Point() { this(0, 0); }              // overload calling another constructor
    Point(int x, int y) { this.x = x; this.y = y; }
}

C

C has no constructors; structs are initialized manually, either via an initializer list at declaration or through a programmer-written "init" function that must be called explicitly and can be forgotten.

struct Point { int x, y; };
struct Point p = { 0, 0 };   /* manual initialization - no guarantee it's always done */

C++

class Point {

    Point(int x, int y) : x(x), y(y) {}  // member initializer list
};

066. Exception Handling

6.1 Exceptions

An exception is an event that disrupts normal program flow, typically due to an error, represented as an object in Python.

try:
    x = 10 / 0
except ZeroDivisionError as e:
    print("Error:", e)
  • All exceptions inherit from the BaseException class (with Exception being the base for almost all user-relevant errors).
  • Python exceptions are unchecked — the compiler/interpreter does not force you to declare or catch them (similar to C++, unlike Java's checked exceptions).

6.2 Handling

try:
    risky_operation()
except (ValueError, TypeError) as e:   # multiple exception types
    print("Handled:", e)
except Exception as e:
    print("Generic handler:", e)
else:
    print("Runs if no exception occurred")
finally:
    print("Always runs — cleanup code")
  • try / except / else / finally blocks. The else clause (unique emphasis in Python, though Java/C++ don't have a direct parallel) runs only if no exception was raised.
  • finally always executes, used for cleanup (closing files, releasing resources), similar to Java/C++.
  • Custom exceptions are created by subclassing Exception.
class InsufficientFundsError(Exception):
    pass

raise InsufficientFundsError("Balance too low")

6.3 Propagation

If an exception is not caught in the current function, it propagates up the call stack to the caller, and further up, until caught or the program terminates with a traceback.

def a(): b()
def b(): c()
def c(): raise ValueError("deep error")

try:
    a()
except ValueError as e:
    print("Caught at top level:", e)   # exception propagated up 3 frames
  • Python shows a full traceback listing every frame the exception passed through.
  • raise (bare) inside an except block re-raises the current exception, preserving the original traceback.
  • raise NewError from original_error allows exception chaining, explicitly showing the causal exception.

6.4 Language Differences (Exceptions)

Java

Java exceptions are objects descending from Throwable, split into checked exceptions (subclasses of Exception, excluding RuntimeException, which the compiler forces you to catch or declare with throws) and unchecked exceptions (RuntimeException and its subclasses, plus Error).

try {
    int x = 10 / 0;
} catch (ArithmeticException e) {
    System.out.println("Error: " + e.getMessage());
}

C

C has no exception mechanism at all. Errors are conventionally signaled through return codes, a global errno variable, or — rarely, for non-local jumps — setjmp/longjmp, none of which carry a structured error object.

FILE *f = fopen("data.txt", "r");
if (f == NULL) { perror("Failed to open file"); }

C++

C++ exceptions are unchecked, like Python's — any type can be thrown (though deriving from std::exception is conventional), and the compiler never forces you to catch or declare them.

try {
    if (denominator == 0) throw std::runtime_error("Division by zero");
    result = numerator / denominator;
} catch (const std::exception &e) {
    std::cout << "Error: " << e.what() << "\n";
}

Java

Java uses try/catch/finally, plus try-with-resources (since Java 7) to automatically close resources like files or streams implementing AutoCloseable, without an explicit finally block.

try (BufferedReader r = new BufferedReader(new FileReader("f.txt"))) {
    System.out.println(r.readLine());
} catch (IOException e) {
    System.out.println("Read failed: " + e.getMessage());
}

C

Without exceptions, C "handles" errors by checking return values immediately after each risky call and branching accordingly — there is no automatic propagation or centralized handling block.

int *p = malloc(sizeof(int));
if (p == NULL) { fprintf(stderr, "Allocation failed\n"); return 1; }

C++

C++ uses try/catch like Java, but has no finally — instead, cleanup is achieved through RAII, since a stack object's destructor runs automatically during stack unwinding when an exception propagates past it.

void process() {
    std::ifstream f("data.txt");   // destructor closes the file automatically,
    // ... even if an exception is thrown below
}

Java

In Java, an uncaught checked exception forces every calling method up the chain to either catch it or declare throws ExceptionType in its own signature — the compiler enforces this all the way up. Unchecked exceptions propagate freely without any such declaration.

void c() throws IOException { throw new IOException("deep error"); }
void b() throws IOException { c(); }
void a() throws IOException { b(); }

C

C has no propagation mechanism — an error must be manually passed up as a return value at every level; forgetting to check and forward it anywhere in the chain silently loses the error.

int c(void) { return -1; }                          /* signals failure via return value */
int b(void) { if (c() < 0) return -1; return 0; }
int a(void) { if (b() < 0) return -1; return 0; }

C++

C++ exception propagation works like Java's unchecked exceptions and Python's — an uncaught exception unwinds the stack, running destructors along the way, until it's caught or reaches main, at which point std::terminate is called.

void c() { throw std::runtime_error("deep error"); }
void b() { c(); }
void a() { b(); }   // exception propagates through b() and a() untouched
